# QuickMemory 设计规范

状态：设计方向与交互约定已落实到 React 页面；已通过构建、交互测试及桌面/手机浏览器验收。具体验证范围见 `docs/VALIDATION.md`，本文保留为后续界面工作的设计依据。

## 依据与适用范围

- 产品需求的原始依据是 `docs/PRODUCT_CONTEXT.md`，它是用户附件的逐字节副本。需求中的硬约束和阶段确认规则优先于本文。
- 设计方法：`ui-ux-pro-max`。检索与适配记录见 `RESEARCH.md`。生成器未给出完整适合本产品的页面模式，因此本文是采用已验证检索结果、按实际产品约束编写的设计方案，不声称整套方案由检索器直接生成。
- 技术边界：React + Vite + TypeScript 桌面 Web，Python + FastAPI + SQLite 本地单用户。生产界面由本地 FastAPI 提供。只有调用用户配置的 LLM 才访问网络。
- 所有界面文案、加载状态、校验错误、空状态和反馈均为简体中文；模型、技术名词和用户原文可保留英文。卡片内容采用纯文本，不渲染 Markdown 或 LaTeX。
- 不增加登录、云端同步、订阅、部署入口、间隔重复、记忆强弱分类或游戏化积分。

## 视觉方向

安静、清晰、便于长时间阅读的学习工作台。主色是深墨绿，底色接近纸张，数据和操作放在白色表面；少量暖色只用于独立的参考提示。采用网格、清晰分隔线、克制的圆角和留白，以内容为中心。

页面应像一本整理良好的学习笔记：标题直接说当前任务，数字清楚可比，概念、参考定义和本人答案有明确的阅读顺序。避免营销首页、巨大宣传横幅、渐变玻璃卡片、聊天气泡、霓虹颜色、装饰性插画或无意义的动画。首页就是工作台。

## 字体、间距与形状

- 字体：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`。只使用本机已有字体；不请求 Google Fonts，不下载字体，不加载 CDN。
- 正文 16px / 1.75；说明 14px / 1.6；表格数字 14–16px；页面标题 28–32px / 1.3；卡片标题 18–20px / 1.5；结果主分数 40–48px，使用等宽数字。常规字重 400，标签 500，标题 600。
- 12px 只供极少量非必要元信息，不承载表单说明、反馈内容或按钮文案。用户文本保留换行（`white-space: pre-wrap`），长英文与 URL 可换行（`overflow-wrap: anywhere`）。
- 间距以 4px 为单位：4 / 8 / 12 / 16 / 24 / 32 / 48。表单项间 20–24px，同组控件 8–12px；段落与下一部分之间 24–32px。
- 内容面板圆角 12px，输入与按钮 8px，标签 6px。仅弹层采用轻阴影；普通卡片靠边框和背景层次分隔。
- 使用同一套本地打包 SVG 描边图标（建议 Lucide），20px 主导航、16–18px 辅助图标。图标不能代替明确动作名，不用 emoji 作为控件。
- 普通 hover/focus 色彩过渡约 120–160ms，展开面板最多 180ms。动画只表达状态变化，不做滚动入场、打字效果或连续闪烁。尊重 `prefers-reduced-motion`。

## 全局框架与响应式

一级导航：`卡片管理`、`文件夹`、`统计看板`、`设置`。`导入题库`从卡片页和文件夹页进入；`考试`、`考试结果`属于文件夹的学习流程，不占用长期导航位。

| 视口 | 布局 |
| --- | --- |
| 1440px | 216–232px 左导航；主内容最大 1160px，32–40px 边距。卡片编辑可采用主编辑区与 300px 辅助区；考试输入居中且宽度约 760px。 |
| 768px | 紧凑导航与主内容并排或顶部导航；24px 边距。卡片编辑和结果改为单列，统计图和列表纵向排列。不得仅靠窄图标栏承担导航。 |
| 375px | 顶部标题与带文字的“打开导航”按钮；导航抽屉可键盘关闭。16px 页面边距，搜索与筛选换行，表格转成带字段名的行卡片。表单按钮可全宽，不锁定屏幕缩放。 |

主滚动区域优先使用文档滚动，避免多层嵌套滚动。除确实需要横向查看的原始代码块外不产生横向滚动；本产品没有代码编辑需求。固定/吸附控件必须预留空间，不能遮挡输入和焦点。

按钮与触摸目标按至少 44×44 CSS px 的产品标准设计；小图标扩大点击区域。可以同时显示“保存卡片”和“AI 核对”，但每个操作区域只能有一个视觉主按钮。

## 页面与核心流程

### 卡片管理

标题及卡片总数 → 搜索框 → 用户标签/文件夹筛选 → 卡片列表。主操作“新建卡片”，次操作“导入题库”。搜索词、筛选、分页和滚动位置在查看卡片后返回时保留。

列表呈现术语、定义摘要、用户标签、所属文件夹和更新时间；点击术语进入详情/编辑。定义全文在详情可读，不把长内容塞进工具提示。标签和错误类型使用不同分组与控件，禁止复用同一筛选字段。

编辑页字段顺序：`术语`、`参考定义`、`参考笔记（选填）`、`用户标签`、`所属文件夹`。说明“参考定义是考试评分的唯一标准”；参考笔记说明“仅用于 AI 核对时提供上下文”。文件夹和标签均可多选。

AI 核对是用户主动点击触发的次操作，返回正确/可能有误/不确定、最多 3 个澄清问题和可选改写。必须展示“AI 核对结果不一定正确，请自行复查”。只在用户点击“采用建议改写”后更新编辑内容，保存仍需明确动作。核对结果不写入数据库；离开编辑页清除。核对失败保留输入。

### 文件夹

展示名称、卡片数量、编辑入口和“开始考试”。进入文件夹后显示卡片集合和导入/导出操作。启动说明“使用本文件夹全部卡片，顺序随机，无时间限制”。空文件夹禁用启动，并提供“添加卡片”或“导入题库”。

同一卡片可同时属于多个文件夹；移出文件夹与永久删除卡片必须使用不同文案。永久删除需要明确展示影响并确认。

### 导入题库

步骤：选择文件或粘贴 JSON → 选择已有/新建目标文件夹 → 重复处理（默认“跳过”，可选“覆盖定义”）→ 预览 → 确认导入 → 导入报告。

预览展示新增、跳过、覆盖、无效数量及前几行；具体结果以服务器校验为准。错误项应能展开查看原因，报告不能只保留短暂 toast。非法 JSON 明确指出格式问题并保留粘贴内容。导入不会触发 AI 核对。导出按钮说明保存本地 JSON 备份，使用数组对象格式。

### 考试

顶部展示文件夹名、`第 3 / 10 题`、本题计时；主区展示术语、宽敞的定义输入框和“提交并继续”。计时记录作答时长，没有倒计时、超时惩罚或红色催促。参考定义在作答期间隐藏。

提交时只等待后端确认答案已保存，随后立即进入下一题，不能等待 LLM 评分。保存失败时停留本题、保留作答、提供重试；重复点击不能产生重复答案。题目切换将焦点移至题目标题或输入区，并适度播报进度。

可显示低强调状态“已提交 3 题 · 正在评分 2 题”。不要逐秒向读屏播报计时或把每次轮询当作通知。离开考试时如有尚未提交的文本，需要保护草稿或给出明确确认。

### 考试结果

上方是本次已完成评分数、待评分数和未评分数。总分/平均值只针对已成功评分的答案并写明分母；有待评分题目时不得把当前平均值称作最终成绩。列表按考试题序稳定排列，轮询到的新评分只更新对应项，不重排列表、不抢焦点。

每题展示最终分数、正确率、完整度、耗时、考试时的参考定义快照与作答原文。评分反馈严格分成“正确的部分 / 错误的部分 / 不确定的部分”。再提供独立的错误类型编辑区和裁判原始分数展开区。

裁判分歧超过 20 时展示“裁判评分差异较大”，显示各裁判的数值和成功/失败状态供比较；不能据此自动扣分。部分裁判失败时说明使用了几个成功结果；全部失败显示“未评分”，分数位置用“—”，不得填 0。

“只重考错题”以已评分且低于配置及格线的题目为准，生成新的考试。仍在评分时说明尚未完成；全部完成且没有错题时显示“没有低于及格线的题目”，不创建空考试。该功能按用户原定计划在第 4 阶段完成。

### 模型知识提示：必须与评分隔离

每道题评分反馈之后，采用浅暖色独立面板，标题逐字使用：`模型提示（不计分，仅供参考）`。

提示正文不能混入三段评分反馈、错误类型、正确率或完整度。面板不显示“扣分”“错误判定”等误导标签；不在三段评分区使用同样的提示背景。若没有提示则不展示空面板。保留模型知识提示供历史查看，但不自动改写卡片。

### 统计看板与卡片历史

以事实数据为中心：作答次数、平均分、最低分、最近分数、平均耗时。不出现“薄弱”“稳定”“掌握度”“待加强”分类，也不据此创建复习算法。

看板包含可按文件夹/用户标签筛选的错误类型分布，以及按平均分升序排列的卡片列表。错误类型用带直接数字标签的横向条形图；同一答案可有多个错误类型，说明统计口径，百分比不能误称互斥比例。图表下提供可读取的数字表。大量类型改用排序列表。

卡片详情提供按时间排列的分数历史与历次作答，每条包含当时的快照、三个反馈区、模型提示与错误类型。时间序列图固定 0–100 纵轴，未评分保留缺口，不能当作 0 分。只有一条记录时显示单点和数值，无记录时显示“还没有考试记录”。

### 设置

分区：`模型连接`、`评分规则`、`错误类型`。提供商预设包含 DeepSeek、Google Gemini、OpenAI、Kimi、Qwen 和自定义兼容选项；模型名可自由填写，不把示例版本写死在逻辑中。

API 密钥默认掩码，显示/隐藏按钮有明确名称。连接配置保存与“测试连接”是可区分的动作；测试显示进行中、成功或可操作的错误说明。说明“卡片保存在本机；核对和评分时会把相关文本发送给你配置的模型服务”。不发送遥测或第三方分析。

裁判数只允许 2/3；正确率和完整度权重清楚显示且合计满足后端规则；及格线默认 60。温度、权重等校验错误贴近字段显示。错误类型可新增、重命名、删除，与用户标签彻底区分。

## 状态规范

| 状态 | 表现与恢复 |
| --- | --- |
| 首次加载 | 内容骨架保持布局，状态文案“正在加载…”；不放无意义闪烁。 |
| 空库 | “还没有卡片”，提供新建卡片和导入题库；不伪造统计数值。 |
| 筛选无结果 | 保留筛选条件，显示“没有符合条件的卡片”和“清除筛选”。 |
| 保存中 | 按钮“正在保存…”，防止重复提交；其他内容保持可读。 |
| 等待评分 | “正在评分”，保留题目、答案和耗时，分数为“—”。 |
| 评分失败 | “未评分”，显示简洁中文原因；不显示伪造分数，不自动把题归为错题。重试入口仅在 API 实际支持后提供。 |
| 合并失败降级 | 仍显示成功裁判聚合数字；说明文字采用第一位成功裁判的三段反馈，明确降级提示。 |
| 本地服务不可用 | 原内容和输入不消失；“暂时无法连接本地服务，请确认服务已启动”及重试操作。 |
| LLM 网络/密钥错误 | “模型服务连接失败”或具体中文原因，给出“检查模型设置”入口；普通卡片管理继续可用。 |
| 表单错误 | 保留输入，字段旁说明原因；多错误时聚焦可链接到字段的错误摘要。 |

## 无障碍与第 3 阶段验收

- 使用语义化标题、按钮、表单和表格；页面有“跳到主要内容”。每个输入有可见 label；图标操作有中文可访问名称；相邻装饰图标隐藏于无障碍树。
- 焦点环 2–3px、外偏移 2px，控件不能因 hover/active 改变尺寸。Tab 顺序与阅读顺序一致。抽屉/模态支持 Esc、限制焦点并在关闭后还原到触发按钮。
- 表单错误使用 `aria-invalid` 和 `aria-describedby`。提交失败后多错误摘要获得焦点；不要每次输入或 blur 都抢焦点。状态更新用温和的 `role="status"`，完成一批评分时播报完整语句。
- 进度同时有文字和数值，颜色永远不单独表达待评分/失败/选中。排序表头支持键盘并使用 `aria-sort`。
- 测试 375 / 768 / 1440px、200% 缩放、仅键盘、简体中文长内容、英文长术语、空数据和大量数据。所有主流程都验证加载、失败、重试以及保留输入。
- 开发检查网络：除本机 API 和用户显式触发的模型请求外，没有字体、图标、分析、图像或 CDN 请求。前端不能获得或输出完整密钥到日志。
- 评分 UI 验收必须包含：慢速评分不阻塞下一题、部分裁判失败、全部失败、合并失败、>20 分歧、未知内容仅进入不计分提示、编辑卡片不改变考试快照。

## 后续实现读取规则

先读原始产品上下文与阶段状态，再读本文；页面存在 `pages/<page>.md` 时补充该页面规则。设计文档不创建 API 端点或更改评分规则；第 3 阶段以第 2 阶段正式确认的 API 契约为准。
